# Context Governance

## 信息优先级与六层分工

遇到冲突时按“用户最新要求 → 当前权威事实源 → 任务台账当前项 → Wiki / 长期记忆 → Compact、聊天与工具缓存”处理；低优先级信息不能静默覆盖高优先级信息。

| 层 | 职责 | 载体 |
| --- | --- | --- |
| 当前上下文 | 最新要求、当前目标、临时判断与本轮工具结果 | 仅当前任务运行时 |
| Compact | 压缩或中断时恢复现场 | 临时摘要，不是项目文件或完成证据 |
| Raw Sources | 保留可追溯的原始输入 | `raw_sources/` |
| Wiki | 把多份资料编译成可查询知识 | `WIKI_INDEX.md`、`wiki/` |
| 长期记忆 | 保存跨会话仍稳定、可复用、可验证的结论 | `MEMORY.md` |
| 任务台账 | 控制当前目标、拆分、状态、阻塞、下一步、验收与证据 | `TASK_LEDGER.md` 或项目既有唯一台账 |

**证据链**贯穿六层：任何完成结论都要指向当前候选、环境、命令、截图、文件、链接或交付物；摘要、Agent 报告和文件存在不能单独证明完成。

## 初始化

用户要求“按上下文治理工作流初始化”时，使用 `scripts/init_project.py <root> --profile durable`。该档位组合两套目录：文章方法的 `AGENTS.md`、`TASK_LEDGER.md`、`WIKI_INDEX.md`、`MEMORY.md`、项目级 `SKILL.md`、`raw_sources/`、`wiki/`、`logs/ingestion/`，以及 Adaptive Delivery 的 `SPEC.md`、`DESIGN.md`、`TECHNICAL.md`、`EVOLUTION.md`。已有文件和目录逐项跳过，不覆盖、不静默合并；符号链接或类型冲突失败关闭。

当前上下文和 Compact 不落盘。项目级 `SKILL.md` 负责路由本项目反复使用的固定风格、专业流程和引用；它不复制全局方法。普通短任务不因方法完整而强制初始化这些文件夹。

## Wiki 编译循环

- **Ingest**：将原始资料原样放入 Raw Sources，记录来源、作者或提供者、日期 / 版本、适用范围、哈希或链接、时效性与冲突状态；摄取日志写入 `logs/ingestion/`。
- **Query**：先从 `WIKI_INDEX.md` 路由到相关 Wiki 页面和权威事实源；只有摘要不足、冲突或需要引用证据时回溯 Raw Sources。外部时效事实重新核验。
- **Lint**：检查失效链接、孤立页面、重复规则、未标来源或版本的结论、尚未显式标记的冲突，以及 Wiki 对权威事实源的越权复制。

Raw Sources 原则上不可变；需要纠正时增加新版本并保留关系。Wiki 是编译层，不是新的产品、视觉或技术事实源。结构化知识必须带来源指针、适用与不适用条件、状态和最后核验时间。

## Compact 与恢复

Compact 至少保留：最新用户要求、当前目标 / Goal / 台账项、关键约束与禁止动作、仓库与候选快照、已完成事项及证据位置、未完成事项、失败路径、阻塞点和唯一下一步动作。恢复后先用当前仓库、唯一台账与权威事实源校验，漂移内容立即失效。

## 长期记忆准入

写入前依次问：**以后还会复用吗**、**有证据来源吗**、**会不会污染后续判断**。只有三问均通过，且结论跨会话稳定、可验证、能说明适用边界时才写入。每条至少记录结论、证据指针、适用范围、核验日期和失效条件；当前进度、临时假设、会话流水、密钥和未经验证的偏好不得进入。

任务结束时分别判断是否更新：事实源因规则或实现变化而更新；任务台账因状态、证据、阻塞或下一步变化而更新；Wiki 因新增可查询知识而更新；长期记忆仅在准入三问通过时更新。没有变化就不机械改文档。
