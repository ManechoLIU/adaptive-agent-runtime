# Methods

## 三档选择

| 可观察条件 | 档位 | 最小输出 | 升级或停止 |
| --- | --- | --- | --- |
| 目标与根因明确、低风险、小范围 | 快速 | 直接改动与定向证据 | 出现跨边界风险则升级；证据通过即停止 |
| 普通功能、UI、跨文件或存在依赖 | 标准 | 目标/非目标、短工作包、依赖、验证 | 依赖或行为不确定时先探索；闭环通过即停止 |
| 认证、费用、外部调用、迁移、安装或发布 | 严格 | 范围冻结、风险矩阵、授权门、恢复证据 | 无授权停在门前；真实门禁通过后停止 |

不要按代码行数机械选档。用户可见行为、持久化和外部副作用比文件数量更重要。

混合请求先拆成可独立交付的工作流，再分别输出“工作流 / 档位 / 证据 / 授权门”；档位不使用单一最高值概括整个请求。只有工作流之间存在真实依赖时，高风险工作流才进入共同关键路径；最终集成仍对每个工作流执行其实际风险要求的证据与授权门。

## 方法路由

- 需求或架构不确定：先做可丢弃的原型或 Spike，只回答未知问题。
- 普通产品功能：按真实用户路径做最小纵向切片。
- 明确 Bug：复现、根因证据、回归、最小修复、定向验证、停止。
- 大量彼此独立的小任务：连续流；同一文件同时只有一个写入者。
- 事故：先止损与恢复，再做根因和回归；不要把重构混入恢复动作。
- 发布候选：完成 diff 审查后冻结快照，按 [Harness and release](harness-and-release.md) 复用验证收据，不直接执行未经授权的发布。
- 长期、多会话、Goal、重复候选或共享环境任务：读取 [long-task governance](long-task-governance.md)，先定位唯一任务台账，并对账与当前范围重叠的候选与副作用。

快速档不输出形式化工作包。只有存在真实依赖、并行价值或高风险边界时才拆分或安排独立审查。并行主体数量按独立关键路径、文件或证据边界和当前执行容量从 `0` 到环境上限动态选择，不以档位或“用了多 Agent”本身作为目标；超出并发容量的工作分波次，并复用已完成主体做交叉审查。

严格档的发布候选或高风险边界在独立执行主体可用时，必须安排非作者审查；独立执行主体是不同 Agent 或人工审查者，同一作者的自审不能替代。这不等于把全部实现交给子 Agent，也不等于主 Agent 应包揽全部实现。主 Agent 保留范围、共享契约、集成、冲突处理与最终验收，只亲自处理共享接缝、阻塞点和未分派范围。实现能通过现有边界或小规模行为不变拆分隔离时优先分派；共享单体文件不是自动放弃并行的理由，先比较最小拆分的成本与风险，只有拆分会扩大范围或破坏交付时才让具体冲突点顺序执行。不得仅以“用户未要求委派”、工作区有未提交改动、主 Agent 能顺序完成或需要统一视觉为由跳过合理分派或独立审查；若独立执行主体不可用，停在审查门前并报告边界。里程碑或剩余范围变化后重新裁剪调度，不机械沿用旧分工。

## 质量保真加速协议

标准档或严格档包含多个结论、多个执行主体或共享事实源时，按以下契约组织工作；快速档不为此增加流程。

1. **冻结证据边界**：记录仓库根、`HEAD`、未提交状态，并列出可独立交付的工作流及本次必须回答的结论。每个工作流标注档位；每个结论只登记直接证据、风险、阻塞关系和停止条件。该清单只服务当前任务，不创建新的项目文档。
2. **一次读取、持续复用**：按事实源完整读取一次，再按证据来源而非问题数量拆分。文件内容或摘要未变化时复用已验证证据，不重复加载同一 Skill、参考文件或事实源。
3. **先走关键路径**：把工作分为阻塞结论、可独立交付结论和等待授权/外部状态的门控事项。门控事项单独停在门前，不阻塞已经具备证据的结论。
4. **分工保持互斥**：不预设“主 Agent 实现 + 一个核查主体”的固定组合。先按关键路径划分可独立交付物，再动态分配 `0` 到环境上限个执行主体；分派后主 Agent 只处理共享契约、未分派范围、集成和冲突，不重复执行相同调查或修改。若主 Agent 同时成为多个可隔离用户可见模块的唯一写入者，而其他主体空闲、只读或重复读取，立即从当前可运行检查点重新拆分，不回退已有有效成果。确实不能低风险拆分的共享冲突点由同一作者持续负责到可运行检查点，不让多个 Agent 轮流编辑同一文件来制造形式上的分工。
5. **草案后定向审查**：事实源明确时，非作者审查优先发生在首个可运行集成版本之后；只有视觉基线、风险边界或根因仍不明确时才先做基线核查。高风险结论、纵向里程碑或严格档由非作者只检查指定结论、反例和遗漏，回报使用“结论 / 证据 / 反例 / 未决项”，不重新做无边界的全量审计。
6. **局部失效与恢复**：仓库快照变化时先比较变更文件和摘要，只让依赖这些变化的结论或验证收据失效；事实源优先级变化、共享契约变化或无法确定影响范围时，才扩大复核范围。同一候选与环境已有通过收据时可以复用；项目验收策略或问题调查要求新证据时记录原因后重跑。
7. **有界等待与可见进度**：单次等待不超过 60 秒；每次等待后检查真实状态，并提供新证据、继续非重叠工作或报告明确阻塞。不得把无 delivered ACK 或 clean 工作树单独视为无进展；按 [long-task governance](long-task-governance.md) 的四类证据和握手恢复规则判定。连续两次确无新证据时停止轮询并恢复调度。

加速只能删除重复读取、重复实施、无边界审查和无效等待，不能删除以下质量门：所有用户问题均有回应；重要结论有当前证据；适用的高风险边界经过独立审查；最终结论针对交付快照复核；未验证部分明确说明边界。时间检查点用于重新调度，不是降低证据标准或草率结束的截止时间。

## 开发阶段启动

用户明确要求进入开发阶段时，标准档或严格档先按项目实际情况输出：

1. 当前里程碑、验收标准、目标与非目标。
2. 工作包、依赖顺序、负责人或 Agent、文件所有权和上下游交付物。
3. 每个工作包的验证证据、停止条件和风险升级点。
4. 主 Agent 的集成、冲突处理、最终验收方式，以及确认后写入当前唯一任务台账的计划。

主 Agent 负责范围、依赖、共享契约、调度、集成、冲突处理与最终验收，不默认承担全部实现；缺少视觉基线或资产时先安排设计工作包；开发 Agent 只实现获分配范围；测试或审查 Agent 在首个可运行版本、里程碑和高风险边界独立验证。现有边界互斥，或能经小规模行为不变拆分形成互斥文件所有权的工作包可以并行；同一文件同一时刻只有一个写入者。超出并发容量的工作按关键路径分波次，已完成的 Agent 可转入交叉审查。

## 调度失效信号

出现任一信号时，从最近可运行检查点重排，不撤销已有有效成果：

- 主 Agent 是多个可隔离用户可见模块的唯一写入者，其他 Agent 空闲或只做无边界审查。
- 多个 Agent 重复完整读取同一批事实源，却没有互斥结论、实现文件或验证责任。
- 仅为满足“使用多 Agent”安排核查，但关键路径上的独立实现仍全部留给主 Agent。
- 以共享单体文件、统一视觉或最终责任为由直接拒绝分派，未先评估最小行为不变拆分。
- 无法形成互斥所有权时，仍让多个 Agent 依次编辑同一共享文件，只是把单人实现变成多次交接。
- Agent 数量和分工沿用启动计划，即使里程碑、剩余范围或实际瓶颈已经变化。

| 用户指令 | 授权边界 |
| --- | --- |
| 进入开发阶段，先制定计划 | 只输出计划，不修改代码、不分派实施；确认后再更新状态账本 |
| 按已确认计划开始开发 | 更新当前唯一任务台账，再分派和执行必要工作 |
| 继续开发 | 对账状态账本与工作区，从当前续接点推进，不重新规划或重做已完成内容 |

## 初始化档案

普通协作型产品默认在项目根目录创建：

`AGENTS.md`、`TASK_LEDGER.md`、`SPEC.md`、`DESIGN.md`、`TECHNICAL.md`、`EVOLUTION.md`。

长期、跨会话、多资料或需要 Goal 恢复的产品使用 `durable` 档位：增加 `MEMORY.md`、`WIKI_INDEX.md` 和项目级 `SKILL.md`，并创建 `raw_sources/`、`wiki/`、`logs/ingestion/` 目录骨架；具体职责与写入条件以 [context governance](context-governance.md) 为准。已有项目只有 `PROJECT_STATUS.md` 时继续把它作为唯一任务台账，不同时创建 `TASK_LEDGER.md`。

一次性脚本、微型库或已有成熟文档体系可裁剪或不初始化，并说明理由。初始化逐个跳过已有文件；不创建空的视觉参考目录。

## 跨会话续接

新会话先对账 Git 根、`HEAD`、`status`、未提交 `diff`，再按 `TASK_LEDGER.md` 优先、`PROJECT_STATUS.md` 兼容的顺序定位唯一任务台账，并读取当前任务涉及的权威文档。共享目录共享文件和 Git，不共享旧聊天。

- `AGENTS.md`：只放极短启动、路由和边界。
- `TASK_LEDGER.md`（或已有 `PROJECT_STATUS.md`）：唯一执行控制面，记录当前目标、决定链接、工作包/所有者、证据、阻塞和下一步；替换过时事实，不追加会话日志。
- `MEMORY.md`：只保存跨会话仍稳定、可复用且可追溯的项目结论，不保存当前进度。
- `WIKI_INDEX.md`：长期项目的结构化知识入口；`raw_sources/`、`wiki/`、`logs/ingestion/` 可以作为初始化目录骨架，但没有真实资料时不得把目录存在称为知识资产或编造索引内容。
- 产品、视觉、技术和经验仍分别归各自权威文档。
