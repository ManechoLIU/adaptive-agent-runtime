# Methods

## 三档选择

| 可观察条件 | 档位 | 最小输出 | 升级或停止 |
| --- | --- | --- | --- |
| 目标与根因明确、低风险、小范围 | 快速 | 直接改动与定向证据 | 出现跨边界风险则升级；证据通过即停止 |
| 普通功能、UI、跨文件或存在依赖 | 标准 | 目标/非目标、短工作包、依赖、验证 | 依赖或行为不确定时先探索；闭环通过即停止 |
| 认证、费用、外部调用、迁移、安装或发布 | 严格 | 范围冻结、风险矩阵、授权门、恢复证据 | 无授权停在门前；真实门禁通过后停止 |

不要按代码行数机械选档。用户可见行为、持久化和外部副作用比文件数量更重要。

混合请求先拆成可独立交付的工作流，再分别输出“工作流 / 档位 / 证据 / 授权门”；档位不使用单一最高值概括整个请求。只有工作流之间存在真实依赖时，高风险工作流才进入共同关键路径；最终集成仍对每个工作流执行其实际风险要求的证据与授权门。

## 方法路由

- 需求或架构不确定：先做可丢弃的原型或 Spike，只回答未知问题。
- 普通产品功能：按真实用户路径做最小纵向切片。
- 明确 Bug：复现、根因证据、回归、最小修复、定向验证、停止。
- 大量彼此独立的小任务：连续流；同一文件同时只有一个写入者。
- 事故：先止损与恢复，再做根因和回归；不要把重构混入恢复动作。
- 发布候选：冻结快照，按发布画像选择 Harness，不直接执行未经授权的发布。

快速档不输出形式化工作包。只有存在真实依赖、并行价值或高风险边界时才拆分或安排独立审查。

严格档的发布候选或高风险边界在独立执行主体可用时，必须安排非作者审查；独立执行主体是不同 Agent 或人工审查者，同一作者的自审不能替代。这不等于把全部实现交给子 Agent。主 Agent 可以保留共享文件并顺序集成，只有文件不重叠且无顺序依赖的工作包才分派实施。不得仅以“用户未要求委派”、工作区有未提交改动或主 Agent 能顺序完成为由跳过独立审查；若独立执行主体不可用，停在审查门前并报告边界。里程碑或剩余范围变化后重新裁剪调度，不机械沿用旧分工。

## 质量保真加速协议

标准档或严格档包含多个结论、多个执行主体或共享事实源时，按以下契约组织工作；快速档不为此增加流程。

1. **冻结证据边界**：记录仓库根、`HEAD`、未提交状态，并列出可独立交付的工作流及本次必须回答的结论。每个工作流标注档位；每个结论只登记直接证据、风险、阻塞关系和停止条件。该清单只服务当前任务，不创建新的项目文档。
2. **一次读取、持续复用**：按事实源完整读取一次，再按证据来源而非问题数量拆分。文件内容或摘要未变化时复用已验证证据，不重复加载同一 Skill、参考文件或事实源。
3. **先走关键路径**：把工作分为阻塞结论、可独立交付结论和等待授权/外部状态的门控事项。门控事项单独停在门前，不阻塞已经具备证据的结论。
4. **分工保持互斥**：标准档默认由主 Agent 加一个证据核查主体完成；只有证据来源、文件和依赖均独立时才增加并行实施。分派后主 Agent 只处理未分派范围、集成和冲突，不重复执行相同调查或修改。
5. **草案后定向审查**：主 Agent 在阻塞证据齐备后先形成草案；高风险结论、纵向里程碑或严格档再由非作者只检查指定结论、反例和遗漏。审查回报使用“结论 / 证据 / 反例 / 未决项”，不重新做无边界的全量审计。
6. **局部失效与恢复**：仓库快照变化时先比较变更文件和摘要，只让依赖这些变化的结论失效；事实源优先级变化、共享契约变化或无法确定影响范围时，才扩大复核范围。
7. **有界等待与可见进度**：单次等待不超过 60 秒；每次等待后检查真实状态，并提供新证据、继续非重叠工作或报告明确阻塞。连续两次没有新证据时按共享约束停止轮询并恢复调度。

加速只能删除重复读取、重复实施、无边界审查和无效等待，不能删除以下质量门：所有用户问题均有回应；重要结论有当前证据；适用的高风险边界经过独立审查；最终结论针对交付快照复核；未验证部分明确说明边界。时间检查点用于重新调度，不是降低证据标准或草率结束的截止时间。

## 开发阶段启动

用户明确要求进入开发阶段时，标准档或严格档先按项目实际情况输出：

1. 当前里程碑、验收标准、目标与非目标。
2. 工作包、依赖顺序、负责人或 Agent、文件所有权和上下游交付物。
3. 每个工作包的验证证据、停止条件和风险升级点。
4. 主 Agent 的集成、冲突处理、最终验收方式，以及确认后写入 `PROJECT_STATUS.md` 的当前计划。

主 Agent 负责范围、依赖、调度、集成与最终验收；缺少视觉基线或资产时先安排设计工作包；开发 Agent 只实现获分配范围；测试或审查 Agent 只在里程碑和高风险边界独立验证。只有无顺序依赖且文件不重叠的工作包才并行，同一文件同时只有一个写入者。

| 用户指令 | 授权边界 |
| --- | --- |
| 进入开发阶段，先制定计划 | 只输出计划，不修改代码、不分派实施；确认后再更新状态账本 |
| 按已确认计划开始开发 | 更新 `PROJECT_STATUS.md`，再分派和执行必要工作 |
| 继续开发 | 对账状态账本与工作区，从当前续接点推进，不重新规划或重做已完成内容 |

## 初始化档案

长期或跨会话协作型产品默认在项目根目录创建：

`AGENTS.md`、`PROJECT_STATUS.md`、`SPEC.md`、`DESIGN.md`、`TECHNICAL.md`、`EVOLUTION.md`。

一次性脚本、微型库或已有成熟文档体系可裁剪或不初始化，并说明理由。初始化逐个跳过已有文件；不创建空的视觉参考目录。

## 跨会话续接

新会话先对账 Git 根、`HEAD`、`status`、未提交 `diff`，再读取 `PROJECT_STATUS.md` 和当前任务涉及的权威文档。共享目录共享文件和 Git，不共享旧聊天。

- `AGENTS.md`：只放极短启动、路由和边界。
- `PROJECT_STATUS.md`：唯一当前状态账本，记录当前目标、决定链接、工作包/所有者、证据、阻塞和下一步；替换过时事实，不追加会话日志。
- 产品、视觉、技术和经验仍分别归各自权威文档。
