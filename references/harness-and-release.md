# Harness and Release

Skill 选择证据层级，不替项目重造测试框架、CI/CD 或发布平台。

| 层级 | 证明什么 |
| --- | --- |
| H0 | 格式、Lint、类型、局部构建 |
| H1 | 单元行为与共享契约 |
| H2 | 服务、数据库、适配器集成 |
| H3 | 真实用户入口到服务和持久化结果 |
| H4 | 经授权的真实外部服务 |
| H5 | 生产产物、安装/部署、迁移、冒烟和回滚 |

快速档选择一个能证明改动的最小层级。标准档覆盖受影响的真实边界。严格档只覆盖适用风险，不因“更完整”自动运行所有层级。

## 验证证据生命周期

验证证据必须绑定到候选内容，而不是绑定到“刚刚运行过”的印象。每份可复用收据至少包含：检查 ID、候选内容快照、命令摘要、结果、依赖的环境输入和失效条件。

1. 修改期间运行能推动当前修复的定向检查，并按需要及时暴露回归；完成前审查实际 diff 并解决已知问题。
2. 完成宣称前冻结候选快照，取得一组与风险相称、对当前候选有效的验证证据。
3. 同一候选快照、环境输入、检查 ID 和命令已有通过收据时可以复用；项目验收策略或问题调查要求新证据时重跑并记录原因。提交元数据变化本身不使内容收据失效。
4. 内容变化只使依赖该变化的收据失效。纯文档变化不自动使代码测试失效；共享契约、测试配置或无法确定影响范围的变化才扩大复验。
5. 外部服务、数据库、权限、时间或部署环境会漂移时，把相关状态作为额外输入或重新核验对应边界；不能用代码快照替代环境证据。
6. 同一快照强制重跑时使用预定义原因：验收策略、问题调查、旧输出缺失或截断、收据无法校验、用户明确要求；不要用含糊理由制造重复工作。

Git 项目可使用 Skill 自带的机械守卫；它只在 `.git/adaptive-delivery/` 保存命令摘要和内容收据，不进入项目文档或提交：

```bash
python3 scripts/verification_guard.py run /path/to/project \
  --check-id full-suite -- python3 -m unittest discover -s tests -v
```

需要把未跟踪的环境配置纳入证据时，增加可重复的 `--input path`。命令原文和输出不会写入收据，避免意外保存凭证；包含秘密的值仍不得放进命令参数。同一快照确需重跑时可用 `acceptance-policy`、`investigation`、`output-unavailable`、`receipt-unverifiable` 或 `user-requested`。

## 发布快速通道

对已经写好、只需提交或推送的候选，顺序为：对账本地与远端 → 审查全部实际 diff 并修完问题 → 冻结候选 → 取得当前验收策略要求的完成证据 → 提交并确认内容快照未变 → 在已授权时推送 → 核对本地、跟踪分支和远端 SHA；远端环境属于验收对象时再执行对应 Harness。

提交钩子、格式化器或生成步骤改变候选内容时，只让受影响收据失效。推送后不重复运行本地完整测试；只有远端构建、部署产物或运行环境本身属于验收对象时，才执行对应的远端 Harness。

## 高风险边界

认证、费用、外部调用、取消、持久化和迁移需要覆盖适用的成功、未配置、认证失败、超时、取消、恢复、幂等与回滚。先读取项目 `TECHNICAL.md`；不要在 Skill 中复制供应商协议或密钥策略。

付费验证必须先确认服务/模型、次数、尺寸或范围、输出位置和预算。未获授权时只做不收费的契约、假服务或本地验证，并明确不能证明真实服务可用。

## 发布画像

- `local`：正式安装包、隔离启动、用户数据、升级、重启、权限和卸载边界。
- `web`：生产构建、Staging、迁移、密钥、观测、灰度、冒烟和回滚。
- `dual`：共享适用的 H0–H4，本地与 Web 分别执行 H5。

独立审查只用于纵向里程碑、发布候选或高风险边界，并必须针对同一仓库根、提交和未提交 diff。审查报告不是完成证据；主 Agent 仍核对实际产物和用户路径。

Git 初始化、提交、远程创建、推送和真实部署分别属于外部状态变更；只执行用户已授权的那一步。
