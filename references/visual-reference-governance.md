# Visual Reference Governance

视觉参考是项目级事实，主 Agent、设计、开发、测试和验收角色共同遵守。

## 状态

- **探索稿**：仅讨论，不归档为有效参考。
- **认可参考图**：用户明确说“作为参考”“按这个开发”“保留给后续角色”等；可带已知瑕疵。
- **运行时资产**：需要单独确认；参考图不会自动成为上线素材。
- **已替代**：从有效基线移出或明确标记，后续不得静默复用。

“不错”“有感觉”等模糊评价不自动升级；若用户已明确认可，不再重复询问是否归档。

## 明确认可后的动作

只执行记录和治理，不擅自开始 UI 实现：

1. 锁定被认可的精确图片；无法取得或无法区分版本时才请用户重新提供。
2. 新项目在首张认可图出现时创建 `design-references/`；现有项目沿用 `development-reference/` 等既有约定，不强制迁移。
3. 保存原图并在 `DESIGN.md` 登记路径、适用范围、采用点、不得照搬的瑕疵和状态。
4. 把采用点转写成可执行视觉规范，而不只保留图片说明。
5. 在 `PROJECT_STATUS.md` 同步当前视觉决定及真正受影响的下一步。

小瑕疵不构成重新生成图片的理由；未经请求和费用授权，不调用图片模型。只有产品行为或技术资产契约确实变化时，才影响扫描 `SPEC.md` 或 `TECHNICAL.md`。

## 使用与验收

视觉任务开始前读取 `DESIGN.md` 及其中登记为有效的精确文件。不得依据 `final`、`v2`、更新时间或“看起来最完整”推断批准。

设计角色延续采用点并避开排除项；开发角色按同一基线实现；测试与验收角色同时检查“应采用”和“不得照搬”；主 Agent 处理替代、冲突和状态同步。聊天记录和每个 Agent 的私有清单都不是视觉事实源。
