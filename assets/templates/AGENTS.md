# 项目协作规则

- 每次任务先固定 Git 根目录并检查 `HEAD`、`status` 和未提交 `diff`；非 Git 项目明确说明。
- 先读取唯一任务台账：优先 `TASK_LEDGER.md`，仅存在 `PROJECT_STATUS.md` 时继续沿用；两者并存先对账，不建立双控制面。
- 再读本任务涉及的 `SPEC.md`、`DESIGN.md`、`TECHNICAL.md`、`MEMORY.md`、`WIKI_INDEX.md` 或 `EVOLUTION.md`，不默认加载无关文档。
- 共享目录共享文件和 Git 状态，不共享旧聊天；不得依赖旧会话补全当前事实。
- 当前上下文和 Compact 不创建项目文件；恢复后的有效状态回写唯一任务台账。
- 保留用户和其他任务的现有修改，不覆盖或回退无关内容。
- 开始新实现前检查相关分支、worktree、未合并候选和共享数据库、端口、进程或产物副作用；发现重叠先对账，不从头重做。
- 证据先于完成宣称；达到当前停止条件立即结束。
- 只有当前事实变化时才更新对应权威文档；状态变化时替换唯一任务台账中的旧事实。
- 用户已要求使用 Goal、要求按长期任务持续推进或本项目已授权自动 Goal 时，一个 Goal 只绑定一个台账项；完成或阻塞前先回写台账。
