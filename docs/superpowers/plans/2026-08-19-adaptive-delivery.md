# Adaptive Delivery 实施计划

## 目标与范围

交付一个最小、可安装、按风险裁剪的 `adaptive-delivery` Skill：窄触发、三档自动裁剪、长期协作项目的六文件初始化、视觉参考治理、证据化验证和独立发布授权门。

本计划是阶段计划，不是逐字施工脚本。每个阶段只保留工作包、文件所有权、依赖、验证和停止条件；不把通用编排、完整测试矩阵或未来扩展提前建出来。Git init、commit、远程创建和 push 始终是独立授权门，本轮不执行。

## 不可变设计约束

- 快速档用于明确、低风险、小范围任务：直接执行并做最小证据；标准档用于普通功能、UI 和跨文件改动：短计划与必要协调；严格档用于认证、费用、外部调用、迁移、安装、部署和发布：完整门禁。
- 自动加载完整 Skill 仅限项目初始化、多阶段交付、跨会话续接、视觉基线治理、Harness/发布和经验提炼。普通问答、单文件简单修改、普通代码审查不因属于软件开发而触发完整编排。
- 所有档位共享的硬约束只有：读取当前事实源和工作区状态、保护已有改动、证据后宣称完成、达到停止条件立即结束。拆包、子 Agent、独立审查和 Harness 随风险条件化。
- 长期或跨会话协作产品默认初始化 `AGENTS.md`、`PROJECT_STATUS.md`、`SPEC.md`、`DESIGN.md`、`TECHNICAL.md`、`EVOLUTION.md` 六个顶层文件；一次性脚本、微型库、成熟文档项目可裁剪或不初始化。已有文件逐个跳过，不覆盖。
- `AGENTS.md` 只做极短启动/路由；`PROJECT_STATUS.md` 是唯一当前状态账本，只替换当前事实，不追加历史。新会话对账 Git 根、`HEAD`、`status`、`diff`、状态账本和权威文档；共享目录共享文件和 Git，不共享旧聊天。
- 新项目视觉目录为 `design-references/`，仅在第一张用户明确认可的参考图出现时创建；现有 `development-reference/` 等约定沿用，不强制迁移。探索稿不入库；获明确认可后归档精确图片，更新 `DESIGN.md` 参考表和可执行规范，记录采用点、不得照搬的瑕疵并同步 `PROJECT_STATUS.md`。小瑕疵不自动重新生成或付费调用，运行时资产另行确认。
- 文档只随对应当前事实更新；`EVOLUTION.md` 仅在有证据且能改变未来行为时维护，不机械追加。

## 文件所有权与依赖

| 工作包 | 主要文件 | 所有权 | 依赖 |
| --- | --- | --- | --- |
| Skill 入口与方法 | `SKILL.md`、`references/methods.md` | Skill 实施 Agent | 本计划与设计规范 |
| 风险证据与视觉治理 | `references/harness-and-release.md`、`references/visual-reference-governance.md`、`references/experience-catalog.md` | Skill 实施 Agent | Skill 入口 |
| 六文件初始化 | `scripts/init_project.py`、`assets/templates/*.md`、`tests/test_init_project.py` | 初始化实施 Agent | 入口路由与模板职责 |
| 结构与行为验证 | `tests/test_skill_structure.py`、`tests/behavioral-scenarios.md` | 验证 Agent | 入口、脚本和参考文件 |
| 普通用户文档 | `README.md` | 文档实施 Agent | 已验证的 Skill 行为 |
| 本地安装 | `~/.agents/skills/adaptive-delivery/`、必要时 `~/.codex/AGENTS.md` | 发布维护者 | 本地验证通过 |
| 发布门 | Git 元数据、远程和推送 | 用户授权后由发布维护者执行 | 所有前置证据 |

同一文件同一时间只有一个写入者。主 Agent 负责范围冻结、快照对账、集成和最终验收；实施 Agent 的报告不能替代主 Agent 对实际 diff 和真实行为的检查。

## 阶段 0：RED baseline（只在 Skill 发布前）

**工作包**

- 创建 `tests/behavioral-scenarios.md`，覆盖：空的长期协作项目、普通功能、明确小 Bug、付费外部 API、发布候选、跨会话续接和视觉参考批准。
- 在不加载新 Skill 的前提下，用独立 Agent 读取原始场景并给出工作方式，记录会遗漏或过度编排的可核查观察。

**验证与停止条件**

- 得到可比较的 RED baseline，或明确记录独立 Agent 不可用的边界。
- 该压力测试只在 Skill 发布前执行一次，不进入每个使用项目的例行流程；完成后进入实现阶段。

## 阶段 1：最小 Skill 入口与按需参考

**工作包**

- `SKILL.md` 只写窄触发、三档选择、四条共享硬约束和资源路由；明确普通问答、单文件简单修改、普通审查不触发完整编排。
- `references/methods.md` 写项目形态、阶段和三档裁剪，以及探索、纵向切片、Bug、发布和事故等必要方法；每种方法只保留触发、证据和停止/升级条件。
- 进入开发阶段时，`methods.md` 用一个紧凑契约区分只规划、按确认计划执行和从当前状态续接，并定义工作包、Agent 协作、文件所有权、验证与主 Agent 验收。
- 以自然语言盲测确认上述三种授权能被识别；若基线已经正确，不向 Skill 入口重复加规则，只在 README 说明快捷写法、当前状态证据和含糊授权边界。
- `references/harness-and-release.md` 写 H0–H5、`local`/`web`/`dual` 发布画像、严格档位的外部边界、同一快照审查和按风险启用的子 Agent/Harness。
- `references/visual-reference-governance.md` 写所有角色共用的批准、归档、参考表、运行时资产和禁止推断规则。
- `references/experience-catalog.md` 写经验条目的证据、适用/不适用条件、项目到全局的审批边界。

**验证与停止条件**

- 结构测试能检查入口长度、frontmatter、引用和无重复的路由边界。
- 入口与参考文件的触发词、三档和停止条件一致；常规小任务不进入完整编排。

## 阶段 2：六文件初始化脚本（TDD）

**工作包**

- 先为 `scripts/init_project.py` 编写失败测试，再实现标准库依赖的幂等初始化。
- 长期/跨会话协作档案默认创建六个文件；脚本、微型库和成熟文档档案支持用户选择裁剪或不初始化，并报告理由。
- 为 `AGENTS.md` 和 `PROJECT_STATUS.md` 提供极短模板；其他模板保持产品、视觉、技术和经验单一职责。
- 每个目标文件独立检查：存在即跳过并保持原字节；初始化不创建空的 `design-references/`，也不覆盖项目运行时资产。

**最小测试面**

- 空协作项目得到且仅得到六个顶层文件。
- 每个已有文件都能独立跳过，内容不变。
- 裁剪档案不误建被裁剪文件；非法项目根目录失败且不写入。
- 重复运行只报告跳过；状态账本模板明确“替换当前事实、不追加历史”。

**验证与停止条件**

- TDD 的 RED/Green 测试全部通过，脚本无第三方运行时依赖；达到上述边界即停止，不扩展通用项目脚手架。

## 阶段 3：README 与当前事实治理

**工作包**

- `README.md` 面向普通用户，按“解决什么、适用/不适用、安装、三档裁剪、六文件初始化、视觉参考例子、验证与授权边界”组织内容。
- 用一张场景总览覆盖初始化、探索、开发计划、开工、跨会话续接、功能/UI、视觉参考、Bug、测试验收、外部服务、发布恢复和经验回流；说明自然语言可以替代固定口令。
- 用简短例子说明：普通小改动走快速档、普通功能走标准档、付费 API 或发布走严格档；用户明确认可图片后才进入 `design-references/`，探索稿不入库且运行时资产另行确认。
- 对照 Skill 和模板检查 README，只陈述已验证能力；提交、推送和发布仍由授权门控制。

**验证与停止条件**

- README 的每一项承诺都能在入口、参考文件或脚本测试中找到依据；过时的默认文档数量表述全部删除。

## 阶段 4：行为验证与发布前压力测试

**工作包**

- 运行初始化、结构和链接测试，按风险执行 Skill 结构校验及本地 smoke test。
- 使用 `tests/behavioral-scenarios.md` 检查：普通问答/单文件修改/普通审查不加载完整编排；普通功能进入标准档；认证、费用、外部调用和发布进入严格档；续接先做状态对账；视觉参考只接受明确批准。
- 在 Skill 发布前由独立 Agent 再做一次盲测，核对 RED baseline 中的遗漏是否被修复；项目使用期间不例行执行这项压力测试。

**验证与停止条件**

- 通过最小确定性测试、代表性行为场景和文档冲突扫描；失败只修复有证据支持的最小规则。
- 若真实外部服务、付费模型或发布环境未获授权，记录未验证边界并停止，不以 fixture 或健康检查替代。

## 阶段 5：本地安装

**工作包**

- 先检查 `~/.agents/skills/adaptive-delivery/` 是否已有内容；有冲突时停止并对账，不覆盖。
- 只安装已验证的入口、参考、脚本、模板、README 和许可证，不带入设计/计划文档、测试夹具或 Git 元数据。
- 必要时在 `~/.codex/AGENTS.md` 增加一条窄触发路由，合并等价规则，不复制完整流程。

**验证与停止条件**

- 安装目录通过 Skill 校验，入口哈希与本地已验版本一致，触发范围仍然窄；不创建远程、不提交、不推送。

## 阶段 6：发布授权门

**工作包**

- 向用户报告测试、行为盲测、安装和范围证据，列明准备发布的精确文件、仓库名、可见性和拟用提交信息。
- 只有用户明确授权后，才可执行 `git init`、`git commit`、远程创建和 `push`；每步都保留可核查结果。

**停止条件**

- 未收到授权即停止在门前；阶段 0–5 可以完成实现、本地验证和经对账的本地安装，但不得执行 Git 初始化、提交、远程创建、推送或公开发布。
